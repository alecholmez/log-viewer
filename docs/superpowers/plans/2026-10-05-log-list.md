# Log list Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use the convergence-loop skill to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Name each log by its date and time, show its length and file name, say what a pull is and why a log has none, fold a log with no pull to one line, give a pull's facts a fixed two-line layout, and open the list on run A.

**Architecture:** The core reads each log's start (the date in the `Log :` header line and the 24-hour clock of the first row), sorts the library by it, and carries, in `overview`, the sentence that says what a pull is and one reason for each log with no pull, all written from the constants `detect_pulls` uses over one shared list of stretches; the golden snapshot reads none of it, so these are tested in a new `crates/core/tests/log_list.rs`. The UI writes the start as `Apr 17, 1:45 pm` from its text, wherever a log is named, and rebuilds the log list from small parts: a log with no pull is one disclosure button until it is opened, a pull shows two lines of facts with Rename under A, B and C, focus survives every rebuild, and the list's own box scrolls to run A once after the library loads.

**Tech Stack:** Rust 2021 (`logviewer-core`: serde, serde_json), TypeScript 5.9 with no framework, Vite 7, Playwright 1.63 (Chromium) for the UI test in `tests/ui.mjs` against the real core over HTTP, Prettier and rustfmt. The Tauri shell and `logviewer-dev` forward `dispatch` and need no change.

**Spec:** `docs/superpowers/specs/2026-10-04-log-list-design.md` (with its amendment of 2026-10-05: the three parts marked "UI review" win where they differ from the rest).

**Starting point:** a new branch cut from `replay-chips` at `9a64dc1`. This plan locates code by quoting it, never by line number. Every quoted "replace" text below was checked by applying this plan's edits, in order, to `9a64dc1` and comparing the result with a build of the plan that passes every check; later tasks quote the code as earlier tasks leave it. ## Decisions

Where the spec is silent or the code forced a choice, this plan decides:

1. **The start is read in `haltech.rs`**, the NSP module, as `local_start(header, first_row)`: the date is the first word of the `Log :` line and must be eight digits with a month of 1 to 12 and a day of 1 to 31; the time is the first row's `hh:mm:ss`, with hours up to 23 and minutes and seconds up to 59; milliseconds are dropped (`13:45:37.026` → `13:45:37`). The spec's "first row with no clock" cannot reach it: the parser starts the data at the first line that begins with a clock and refuses a file with none (`The log has no data rows.`).
2. **`startedAt` is always in `logs`**, as text or `null`, and is a new field beside `start`; the key, built from `start`, does not change.
3. **The order is one sort key**, `(no start, start text, file name)` in `refresh`; the start text is `YYYY-MM-DDThh:mm:ss`, so it sorts as time. The sample logs' order does not change, so neither does the golden snapshot. Two expectations in `crates/core/tests/library.rs` that relied on name order are updated in Task 1 (a log stored as `… (2).csv` holds a later log, so it is now second).
4. **`overview` carries the sentence and the reasons as `pullRule` and `noPulls: [{ logKey, reason }]`**, through a reply struct that flattens `Overview` in `dispatch`. `Session::overview()` and `Overview` do not change, so the golden snapshot, which serialises `Overview`, does not see them; they are tested in `crates/core/tests/log_list.rs`, as the spec asks.
5. **One list of stretches** (`stretches` in `dyno.rs`) feeds both `detect_pulls` and `why_no_pull`, so the reason cannot disagree with the rule. It is the old loop of `detect_pulls`, unchanged; the golden snapshot pins the pulls.
6. **How a reason is chosen and written.** In gear and moving are read over every sample. The pedal's peak is the highest reading of the core's pedal role (the throttle when a log has no pedal channel); when the log has no reading at all it is NaN and the pedal line is skipped. `reached` is written whole (`54%`); `peaked` with one decimal (`14.7%`): NSP logs the pedal in tenths, so a peak under 15 never reads `15.0`. The stretch named is the longest by time among stretches of two samples or more, the first of two as long; its gain is whole rpm, and its length is in tenths unless tenths would read the 1.2 s a pull needs while it is shorter, then in hundredths (or thousandths): `1.18 s`. A log whose stretches are all one sample long gets the last line. The spec's "no speed channel" can only be a speed channel with no reading: a log with no Vehicle Speed channel at all is refused on import today (`This log has no RPM or Vehicle Speed channel.`). A speed channel with no reading reads as never moving, and a log with no gear channel as never in gear; both are tested.
7. **The length is rounded to whole seconds first**, then written `41 s` or `3 min 34 s` (`1 min 0 s` at 60). The spec's closed line `70 s · No pulls` is the 1:36 pm log, 69.743 s long; by the spec's own rule that is `1 min 10 s`, which this plan writes and tests.
8. **The title is built from the core's text** by `startLabel` in `src/state.ts`: a regular expression takes year, month, day, hour and minute; the month is a name from a list; the hour is 12-hour with 12 for noon and midnight, then ` am` or ` pm`; the year is added when it differs from `new Date().getFullYear()`. No `Date` parsing, no `Intl`, so the machine's zone cannot move it. The UI test computes the expected day from the machine's year, so it keeps passing after 2026, and opens one window in `Pacific/Kiritimati` (UTC+14) with its clock set to 2027 to see the same time with `, 2026`.
9. **Rename starts from the date and time:** the field holds the log's name, or its date and time when it has none, selected, so typing replaces it. Keeping it as it is, or clearing it, keeps no name (`v && v !== logDefault(log)`). Pulls keep today's field (empty, with the default as placeholder).
10. **A finding's occurrence names the log as everything else does:** `o.label + ', ' + logName(o.log) + ' ' + seconds + ' s'`. The old `.replace(/ log$/, '')` goes; it also cut ` log` off a name the person gave.
11. **What a pull is goes directly under the panel title**, before `A is replayed. B and C overlay on the charts.`, as a `.hint`, hidden while the library is empty; its text is the core's `pullRule`.
12. **The file name line spans the whole entry**, under the length and the actions, so the sample logs' names are whole in the 344 px rail; it is `--ink-3` with an ellipsis and its whole name in `title`. It is left out only when the log has no start (then the title is the file name).
13. **A log with no pull is a `button.log-toggle` holding the title and `… · No pulls`**, with `aria-expanded` and `aria-controls` naming `div.log-more` (hidden while closed), which holds what any log shows and the reason. Rename replaces the whole button with the name field (an input inside a button is not allowed and would toggle the log on every key).
14. **Which logs are open:** `openLogs` in `src/app.ts`, flipped by the button. When the replay comes to a log (its log changes to that one, from Replay, a finding or the app opening on a log), that log is added once, so its actions are at hand; the person can close it again even while it is replayed, rather than meet a button that does nothing, and nothing closes a log on its own. Not saved. A log with pulls has no button and is always open.
15. **Focus survives a rebuild.** Opening and closing change the list in place (`syncLogs`), so the button keeps focus. Every control in the list carries a `data-fid`, and `renderLogs` gives focus back to the control with the same `data-fid`, without scrolling; the name field carries its Rename button's `data-fid`, so focus returns to Rename after Enter or Escape, whose key press is spent with `preventDefault` (without it the same press then pressed the new Rename button: found while measuring).
16. **`syncLogs` runs from `renderStats`**, which already follows what the replay shows (it writes the replay's label), and at the end of `renderLogs`.
17. **A pull's row:** two `.meta.fact` lines, each `white-space: nowrap` with an ellipsis, so a line can never wrap and no separator can hang. A named pull shows its gear and RPM range on its own line under the name, above the two lines ("what a renamed pull shows does not otherwise change"). Rename is a text action in `.pull-side`, under `.ab`, right-aligned with it.
18. **A pull with no manifold pressure reading has no peak pressure:** `peak_map` starts as NaN, so it is `null` in JSON and the row leaves `· 138 kPa` out. A pull always has pedal readings (15% or more), so the pedal fact is never missing in practice; the row handles both the same way.
19. **"The rail's narrowest width" is 344 px**: the rail column is 344 px at every window wider than 860 px; at 860 px and below the list takes the window's width, which is wider (358 px on a 390 px phone). The test runs at 1400 px and checks the rail is 344 px.
20. **Run A in view:** after the library first loads (`openLibrary`, once the fonts are in) the nearest scrolling box around run A's row (the rail beside the charts, `#logs` in one column) gets a new `scrollTop`, so the page never moves and nothing animates; the row is brought inside the part of the box on screen, with a 12 px margin. Measured with Tasks 1 to 6 in place: at 1400 × 900 run A is already in view (row 820 to 888 px, rail 95 to 967 px), so the spec's check passes without scrolling; Task 7 also opens at 1400 × 700, where the box must scroll 200 px, and checks that choosing a run later does not scroll it again.
21. **How the tests find a log:** by text in it (`logAction(title, label)`, which clicks the log's own `.links button` and opens a closed log first); a pull by its row. The undated log is added through the core's `load_text` and then shown in a new window: a window that opens scans the watch folder, and files added through the page while a scan runs are not imported. The screenshot script finds the 1:45 pm log by its file name, which does not depend on the year.
22. **Styles:** `.log-toggle` joins the transition, `:active` and touch lists; no token is added; the closed line's quiet text and the file name use `--ink-3`.
23. **The spec and this plan are untracked at `9a64dc1`.** Earlier specs and plans were committed on their own (`Spec: …`, `Plan: …`) before their first task; commit these two the same way before Task 1. Task 8 changes the spec's status line and stages the spec by name.

```rust
//! What the log list shows, as the core gives it: each log's start and the library's order.

mod common;

use std::fs;

use common::{call, root, sample_session};
use logviewer_core::Session;
use serde_json::json;

/// A small NSP log: the `Log :` header line (None for a log without one), then the channels as (name, NSP type, raw
/// samples as NSP writes them: Speed and Percentage in tenths), one row every `ms` milliseconds from `clock`, which is
/// the hour and minute (`13:00`) the log starts at, on the minute. Every log needs RPM and Vehicle Speed.
fn nsp(
    header: Option<&str>,
    clock: &str,
    ms: usize,
    channels: &[(&str, &str, Vec<f64>)],
) -> String {
    let mut text = String::from("%DataLog%\n");
    for (name, ty, _) in channels {
        text += &format!("Channel : {name}\nType : {ty}\n");
    }
    if let Some(h) = header {
        text += &format!("Log : {h}\n");
    }
    for i in 0..channels[0].2.len() {
        let t = i * ms;
        text += &format!("{clock}:{:02}.{:03}", t / 1000, t % 1000);
        for (_, _, v) in channels {
            text += &format!(",{}", v[i]);
        }
        text += "\n";
    }
    text
}

/// RPM as given and the car standing still, 50 ms apart. The RPM samples make each log's bytes its own.
fn idle(header: Option<&str>, clock: &str, rpm: &[f64]) -> String {
    let still = vec![0.0; rpm.len()];
    nsp(
        header,
        clock,
        50,
        &[
            ("RPM", "EngineSpeed", rpm.to_vec()),
            ("Vehicle Speed", "Speed", still),
        ],
    )
}

fn sample(name: &str) -> String {
    fs::read_to_string(root().join("testdata/logs").join(name)).expect("sample log")
}

/// Each log in the library as (file name, start), in the library's order.
fn starts(s: &mut Session) -> Vec<(String, Option<String>)> {
    let logs = call(s, "logs", json!({})).unwrap();
    let logs = logs.as_array().unwrap();
    logs.iter()
        .map(|l| {
            let at = l["startedAt"].as_str().map(str::to_string);
            (l["name"].as_str().unwrap().to_string(), at)
        })
        .collect()
}

fn local_start(header: &str, first_row: &str) -> Option<String> {
    let date = header.split_whitespace().next()?;
    let clock = first_row.get(..8)?;
    if date.len() != 8 || !date.bytes().all(|b| b.is_ascii_digit()) {
        return None;

pub fn pull_rule() -> String {
    format!(
        "A pull is RPM rising in one gear, with the car moving and the accelerator pedal at {}% or more, for at least {} s and {} rpm.",
        num(MIN_PEDAL),
        num(MIN_DUR),
        n0(MIN_GAIN)
    )
}

/// Why a log has no pull, in the log's own numbers: the first reason that applies, written from the constants
/// `detect_pulls` uses. For a log with no pull only. A log with no gear or no speed reading reads as never in gear or
/// never moving.
pub fn why_no_pull(log: &Log) -> String {
    let (t, ch) = (&log.t, &log.ch);
    let in_gear = ch.gear.iter().any(|&g| g >= 1.0);
    let moved = ch.vss.iter().any(|&v| v >= MIN_SPEED);
    // NaN when the log has no reading of the pedal at all
    let pedal = ch.pedal.iter().copied().fold(f64::NAN, f64::max);
    // "but I did press it"
    let pressed = if pedal >= MIN_PEDAL {
        format!(" The accelerator pedal reached {}%.", n0(pedal))
    } else {
        String::new()
    };
    if !in_gear && !moved {
        return format!("No pulls: the car stayed out of gear and did not move.{pressed}");
    }
    if !in_gear {
        return format!("No pulls: the car stayed out of gear.{pressed}");
    }
    if !moved {
        return format!(
            "No pulls: the car stayed under {} km/h.{pressed}",
            num(MIN_SPEED)
        );
    }
    if pedal < MIN_PEDAL {
        return format!(
            "No pulls: the accelerator pedal peaked at {}%, under the {}% a pull needs.",
            fx(pedal, 1),
            num(MIN_PEDAL)
        );
    }
    // the longest stretch of two samples or more; the first of two as long
    let mut longest: Option<(usize, usize)> = None;
    for (a, b) in stretches(log) {
        if b > a && longest.is_none_or(|(x, y)| t[b] - t[a] > t[y] - t[x]) {
            longest = Some((a, b));
        }
    }
    let Some((a, b)) = longest else {
        return format!(
            "No pulls: RPM never rose in gear with the accelerator pedal at {}% or more.",
            num(MIN_PEDAL)
        );
    };
    let dur = t[b] - t[a];
    // a stretch just short of the time a pull needs is never written as that time: 1.17 s, not 1.2 s
    let lasted = (1..=3)
        .map(|d| fx(dur, d))
        .find(|s| dur >= MIN_DUR || s.parse::<f64>().is_ok_and(|v| v < MIN_DUR))
        .unwrap_or_else(|| fx(dur, 3));
    format!(
        "No pulls: the longest stretch of rising RPM in one gear lasted {lasted} s and gained {} rpm. A pull needs {} s and {} rpm.",
        n0(ch.rpm[b] - ch.rpm[a]),
        num(MIN_DUR),
        n0(MIN_GAIN)
    )
}
```

`stretches` is the old loop of `detect_pulls` with the push of a pull taken out, so the pulls are the same; the golden test checks it. `why_no_pull` follows Decision 6: the comparisons `>= 1.0`, `>= MIN_SPEED` and `>= MIN_PEDAL` are false for NaN on purpose (a missing sample is not in gear, not moving and not pressed, as in the rule), and `pedal` folds with `f64::max` from NaN, so it stays NaN only when the log has no pedal reading at all.

 * with the year when it is not this year: "Apr 17, 2025, 1:45 pm". Read from the text, never through Date, so the zone
 * the machine is set to cannot move it.
 */
export function startLabel(at: string): string {
  const year = new Date().getFullYear();
  const m = /^(\d{4})-(\d\d)-(\d\d)T(\d\d):(\d\d)/.exec(at);
  if (!m) return at;
  const h = +m[4];
  return (
    MONTHS[+m[2] - 1] + ' ' + +m[3] + (+m[1] === year ? '' : ', ' + m[1]) + ', ' + (h % 12 || 12) + ':' + m[5] + (h < 12 ? ' am' : ' pm')
  );
}

/** A log's name when the person has not named it: its date and time, or its file name without the extension when the core could not read its start. */
export function logDefault(log: Log): string {
  return log.startedAt ? startLabel(log.startedAt) : log.name.replace(/\.csv$/i, '');
}

/**
 * Put a name field in place of what `holder` holds. `from` is the Rename button the edit started from: the field takes its
 * `data-fid`, so when the list is rebuilt after the edit, focus goes back to that button.
 */
function startRename(
  holder: HTMLElement,
  current: string | undefined,
  fallback: string,
  commit: (v: string | null) => void,
  from: HTMLElement,
): void {
  const inp = el('input', 'rename');
  inp.type = 'text';
  inp.value = current || '';
  inp.placeholder = fallback;
  inp.setAttribute('aria-label', 'Name');
  if (from.dataset.fid) inp.dataset.fid = from.dataset.fid;
  holder.textContent = '';
  holder.appendChild(inp);
  inp.focus();
  inp.select();
  let done = false;
  const finish = (ok: boolean) => {
    if (done) return;
    done = true;
    commit(ok ? inp.value.trim() : null);
  };
  inp.addEventListener('keydown', e => {
    if (e.key !== 'Enter' && e.key !== 'Escape') return;
    // the key is spent here: focus moves to the Rename button as the list is rebuilt, and the key must not press it
    e.preventDefault();
    finish(e.key === 'Enter');
  });
  inp.addEventListener('blur', () => finish(true));
}

async function removeLog(log: Log): Promise<void> {
  try {
    await api.removeLog(log.key);

function syncLogs(): void {
